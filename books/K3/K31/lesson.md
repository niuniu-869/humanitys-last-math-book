## K3.1 · 复杂度：程序要跑多少步

推荐系统要在几十毫秒内，从上亿件商品里挑出几十件摆给你。假设一台机器每秒能完成 $10^9$ 次基本操作，而一次推荐必须在 50 毫秒内完成，那它最多做 $5\times10^7$ 步；若有 $10^8$ 件商品，即使每件只比较一次，也要 0.1 秒，已经超出了这次设定的时间，所以它不可能把每件商品都和你的喜好认真比一遍。同一个任务，换一种做法，运行时间可以从 3 秒缩到 0.003 秒，也可以从 1 秒涨到 1 年。怎样在程序写出来之前就知道它属于哪一种，是这一章要解决的问题。

办法是数步数：把程序执行的基本操作次数写成关于输入规模 $n$ 的式子，再只看它增长的快慢。机器的秒数会随硬件改变，不是程序自己的性质，所以 1965 年哈特马尼斯（Hartmanis）和斯特恩斯（Stearns）提出按计算所需的步数来衡量难度。可是数出来的式子形状各异，还需要一种只留下增长快慢的说法：高德纳（Knuth）在 1976 年把 $O$、$\Omega$、$\Theta$ 这组记号推广成分析算法的通用语言，本章用它们分别表示增长速度的上界、下界和同阶。

这一章按下面的顺序展开。第 1 节学读伪代码，并用追踪表把一段程序在具体输入上走一遍，后面每一章都要用。第 2 节把循环的次数写成求和。第 3、4 节解决「只看增长最快的那一项」的道理，并用极限给 $\log n$、$n^k$、$2^n$、$n!$ 排座次。第 5 节讲递归，并用归纳法证明递归程序算得对。第 6、7 节写出递归程序的运行时间，先用展开法和递归树，最后得到一个能直接写出答案的公式（主定理）。

### 1. 一段伪代码在做什么？

读一段程序，最可靠的办法是拿一组具体的输入，像电脑那样一步一步走。伪代码是给人读的程序，本书统一这样写（先扫一眼，读到后面的程序时再回来查）：

- 赋值用左箭头：`x ← 5` 表示把 5 存进 $x$。
- 数组 $A$ 有 $n$ 项，下标从 1 开始，第 $i$ 项写 `A[i]`。
- `for i ← 1 to n` 表示 $i$ 依次取 $1,2,\dots,n$，每取一个值就做一遍下面缩进的语句；$n<1$ 时一遍也不做。
- `while 条件` 表示条件成立就做缩进的语句，做完再检查条件，直到条件不成立。
- `if 条件`（可以接 `else`）表示条件成立才做缩进的语句。
- 哪些语句属于哪一层，只看缩进。
- `return` 把结果交回去，同时结束整个函数。
- $\lfloor x\rfloor$ 读作「$x$ 向下取整」，是不超过 $x$ 的最大整数，例如 $\lfloor 18.5\rfloor=18$。

本书的第一个老朋友是数组 $A=[5,2,8,1,9,3]$，$n=6$。先看一段找最大值的程序（要求数组非空，$n$ 不超过数组的长度）：

```
MAX(A, n)
    m ← A[1]
    for i ← 2 to n
        if A[i] > m
            m ← A[i]
    return m
```

**方法 1（追踪表）**

1. 列出程序里出现的每个变量，每个变量占一列，再加一列记「当前执行到哪一步」。
2. 从第一行开始，每执行一次赋值或一次循环，就在表里写一行，记下之后各变量的值。
3. 遇到 `if`，在表里写明条件是真还是假，假的话缩进里的语句不执行。
4. 循环结束、`return` 时停笔，最后一行就是结果。

**例 1**　用追踪表跟踪 `MAX(A, 6)`，$A=[5,2,8,1,9,3]$。

先写出初始状态：执行第一句以后 $m=5$。然后 $i$ 从 2 走到 6，每一轮比较 `A[i]` 与当前的 $m$：

| $i$ | `A[i]` | $A[i]>m$？ | 之后的 $m$ |
|---|---|---|---|
| （开始） | | | 5 |
| 2 | 2 | 假 | 5 |
| 3 | 8 | 真 | 8 |
| 4 | 1 | 假 | 8 |
| 5 | 9 | 真 | 9 |
| 6 | 3 | 假 | 9 |

循环结束，返回 9。表里 $m$ 那一列每次要么不变，要么换成更大的数，所以它始终是「已经看过的各项里的最大值」。这句话在 K3.2 会变成证明排序正确的工具，叫循环不变量。

> 追踪下面的程序在 $A=[5,2,8,1,9,3]$、$x=4$ 上返回什么。
>
> ```
> COUNT(A, n, x)
>     c ← 0
>     for i ← 1 to n
>         if A[i] > x
>             c ← c + 1
>     return c
> ```
>
> 答案：$i=1,\dots,6$ 时 $A[i]>4$ 依次为真、假、真、假、真、假，$c$ 依次变成 1、1、2、2、3、3，返回 3。它数出数组里大于 $x$ 的项有几个。

`for` 通常直接列出变量要取的值，`while` 用条件决定是否继续。两者的实际次数都要结合循环体和提前 `return` 来判断，`while` 的次数也常能在运行前推导出来。

**例 2**　这一道和例 1 的区别在于循环换成了 `while`，要根据条件和变量的变化推导次数。追踪 `HALVE(37)`。

```
HALVE(n)
    k ← 0
    while n > 1
        n ← ⌊n / 2⌋
        k ← k + 1
    return k
```

每进一轮先检查条件 $n>1$，再执行两句：

| 轮数 | 进入时 $n>1$？ | 之后的 $n$ | 之后的 $k$ |
|---|---|---|---|
| （开始） | | 37 | 0 |
| 1 | 真 | 18 | 1 |
| 2 | 真 | 9 | 2 |
| 3 | 真 | 4 | 3 |
| 4 | 真 | 2 | 4 |
| 5 | 真 | 1 | 5 |

此时 $n=1$，条件为假，循环结束，返回 5。因为 $2^5=32\le37<64=2^6$，所以返回的恰好是 $\lfloor\log_2 37\rfloor$。每一轮把 $n$ 减半，减到 1 要几轮，这就是第 2 节里「减半循环」的来源。

**例 3**　这一道和例 1 的区别在于循环里套了循环，要同时盯两个下标。追踪 `PAIRS(A, 6)`。

```
PAIRS(A, n)
    c ← 0
    for i ← 1 to n − 1
        for j ← i + 1 to n
            if A[i] > A[j]
                c ← c + 1
    return c
```

外层固定一个 $i$，内层让 $j$ 扫过它后面的每一项，所以每一行记一整个外层：

| $i$ | `A[i]` | 后面比它小的项 | 之后的 $c$ |
|---|---|---|---|
| 1 | 5 | 2, 1, 3 | 3 |
| 2 | 2 | 1 | 4 |
| 3 | 8 | 1, 3 | 6 |
| 4 | 1 | 无 | 6 |
| 5 | 9 | 3 | 7 |

返回 7。`PAIRS` 数的是「前面的数反而比后面的大」的数对个数，K3.2 把它叫作逆序对，这个 7 会在那里一再出现。

每张表只回答了一个具体输入上的情形，输入一长，表就得重画。能不能一次写出对所有 $n$ 都成立的次数？这是下一节的问题。

合上书，只凭本节开头的语句说明，给 `HALVE(100)` 做一张追踪表，并说出返回值。

### 2. 这段程序要执行多少次基本操作？

追踪能告诉我们结果，却回答不了「输入变成 100 万项要多久」。不过表本身已经带着线索：例 1 追踪 $n=6$ 的数组，比较那一列有 5 行；数组再长一项就多一行，所以 $n$ 项是 $n-1$ 行。把这种「次数怎样随 $n$ 变」对各种循环都写成式子，就是这一节要做的事。

先约定数什么。**基本操作**是每次只花固定时间的操作，例如比较两个数、做一次加法、一次赋值。我们选一种在程序里反复出现的操作来数，通常选最里层循环里的比较。选哪一种并不重要，只要它的次数和总工作量成固定倍数，后面的结论就不变。本章按一个简化的约定计数：一次加法、乘法、比较或赋值各算一步，存放一个数算一个存储位置，暂不计数字位数变长带来的额外计算和存储。

数循环次数用求和。$\sum_{k=1}^{m}a_k$ 读作「$a_k$ 从 $k=1$ 加到 $k=m$」。本章只用三个结论，前两个已在 Z.4.5 讲过，其中平方和是用归纳法证明的：

$$\sum_{k=1}^{m}k=\frac{m(m+1)}{2},\qquad\sum_{k=1}^{m}k^2=\frac{m(m+1)(2m+1)}{6},\qquad\sum_{k=0}^{m}2^k=2^{m+1}-1 .$$

第三个当场就能推出：记 $S=\sum_{k=0}^{m}2^k$，则 $2S$ 比 $S$ 多出最后一项 $2^{m+1}$、少了第一项 1，所以 $2S-S=2^{m+1}-1$。

**方法 2（数基本操作）**

1. 选定基本操作，通常是最里层的比较。
2. 从最里层往外数：先写出里层循环对于固定的外层变量要做几次，这个次数常常依赖外层变量。
3. 把外层变量从头取到尾，对这些次数求和。
4. 用 $n=3$ 或 $n=6$ 代进去，和追踪表里数出来的次数核对。

**例 4**　例 1 和例 3 的追踪表只数出了 $n=6$ 时的次数，现在对一般的 $n$ 写出式子。数 `MAX(A, n)` 和 `PAIRS(A, n)` 里的比较次数。

`MAX` 的比较在 「$A[i]>m$」，$i$ 取 $2,\dots,n$，共 $n-1$ 次。例 1 里 $n=6$，表里恰好有 5 行。

`PAIRS` 的比较在 「$A[i]>A[j]$」。固定 $i$，$j$ 取 $i+1,\dots,n$，内层做 $n-i$ 次，所以

$$\sum_{i=1}^{n-1}(n-i)=(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}{2}.$$

这里把外层变量换成 $k=n-i$，从 $n-1$ 倒数到 1，就是前 $n-1$ 个正整数之和。$n=6$ 时是 $5+4+3+2+1=15$，也就是 6 个数两两比一次的总数：例 3 的外层有 5 行，内层分别扫 5、4、3、2、1 项，合计 15 次比较（例 3 的表里记的 $c$ 只数其中「前大后小」的 7 次）。

> 数下面这段程序里 `s ← s + 1` 执行的次数（$n=6$ 时是多少？）。
>
> ```
> for i ← 1 to n
>     for j ← 1 to i
>         s ← s + 1
> ```
>
> 答案：固定 $i$，内层做 $i$ 次，总数 $\sum_{i=1}^{n}i=\frac{n(n+1)}{2}$，$n=6$ 时是 21。

**例 5**　这一道和例 4 的区别在于内层不再是按顺序走一遍，而是每次把变量乘 2。数下面程序里 `j ← 2 * j` 执行的次数。

```
for i ← 1 to n
    j ← 1
    while j ≤ n
        j ← 2 * j
```

外层每次内层都是同样的，所以先数内层。$j$ 依次取 $1,2,4,\dots,2^t$，只要 $2^t\le n$ 就做一次，即 $t\le\log_2 n$，$t$ 可取 $0,1,\dots,\lfloor\log_2 n\rfloor$，共 $\lfloor\log_2 n\rfloor+1$ 次。例如 $n=8$ 时 $j=1,2,4,8$ 各做一次，$j=16$ 停止，共 4 次。

外层重复 $n$ 遍，总数为

$$n\bigl(\lfloor\log_2 n\rfloor+1\bigr),\qquad n=8\ \text{时}\ 8\times4=32 .$$

从这道题以后，每看到「变量每次乘 2（或除以 2）」的循环，就想到它只跑 $\log_2 n$ 级别的次数。

**例 6**　这一道把例 4 的双层循环搬到一个真实场景，结构完全一样，只是循环体换成了「算一个分数」。语言模型把一段文字切成 $n$ 个词，注意力这一层要给每个词与每个词（包括它自己）各算一个相关分数，存成 $n\times n$ 的表。程序结构就是两层循环：

```
for i ← 1 to n
    for j ← 1 to n
        S[i][j] ← 词 i 与词 j 的相关分数
```

这个分数具体怎么算现在不必知道，把它当一次基本操作。分数的个数是 $n\cdot n=n^2$。上下文有 1000 个词时是 $10^6$ 个，128000 个词时是 $16\,384\,000\,000$，约 $1.6\times10^{10}$ 个：长度变成 128 倍，工作量变成 $128^2=16384$ 倍。如果每个词只看自己和它前面的词，$j$ 只取 $1,\dots,i$，次数变成例 4 后面那道题里的 $\frac{n(n+1)}{2}$，省了近一半，但长度翻倍时工作量仍然接近翻 4 倍（精确的倍数是 $\frac{2(2n+1)}{n+1}$，随 $n$ 增大趋于 4）。

#### 次数只由 $n$ 决定吗？

**例 7**　前面的程序次数只依赖 $n$，这一道的次数还依赖输入，要分情况数。顺序查找：

```
SEARCH(A, n, x)
    for i ← 1 to n
        if A[i] = x
            return i
    return 0
```

在 $A=[5,2,8,1,9,3]$ 里找 $x=8$，比较 3 次就返回 3；找 $x=7$，比较 6 次都不等，返回 0。同样是 $n=6$，次数从 1 次（$x=5$）到 6 次都有可能。

所以要区分三种数法：**最好情况**是对所有规模为 $n$ 的输入取最少的次数，这里是 1；**最坏情况**是取最多的次数，这里是 $n$；**平均情况**要先说清输入怎样分布。若保证查找成功，且第一次找到 $x$ 的位置在 $1,\dots,n$ 中等可能，比较次数 $1,2,\dots,n$ 各以 $\frac1n$ 的概率出现，平均是 $\frac{n+1}{2}$。本书如果没有另外说明，说一个算法的运行时间指的是**最坏情况**，因为它是对任何输入都成立的保证。

这一节把程序变成了式子：$n-1$、$\frac{n(n-1)}{2}$、$n(\lfloor\log_2 n\rfloor+1)$、$n^2$。接下来的问题是，这些式子长得并不一样，哪些细节可以丢掉。

合上书，说出方法 2 的四步，并用它数出例 4 中 `PAIRS` 的比较次数。

### 3. 为什么只看增长最快的那一项？

假设某个程序的操作数是 $f(n)=3n^2+5n+20$。把 $f(n)$ 和 $n^2$ 的比值列出来：

| $n$ | $f(n)$ | $f(n)/n^2$ |
|---|---|---|
| 10 | 370 | 3.7 |
| 100 | 30520 | 3.052 |
| 1000 | 3005020 | 3.00502 |
| $10^6$ | $3\,000\,005\,000\,020$ | $\approx3.000005$ |

$n$ 越大，比值越接近 3，$5n$ 和 20 几乎没有影响。而 $3$ 这个倍数在换一台快一倍的机器、换一种编程语言时也会变。所以我们想要一种说法，只保留「增长得有多快」，既忽略低次项，也忽略常数倍。

#### 怎样用定义说「增长一样快」？

以下只关心 $n$ 足够大时的情形。设 $f(n)$、$g(n)$ 从某个正整数起有定义且为正（常取操作数；它们在少数较小的规模处取 0，不影响比较）。下面的 $n_0$ 取正整数，所用的常数不随 $n$ 改变。

- 如果存在常数 $c>0$ 和 $n_0$，使得 $n\ge n_0$ 时 $f(n)\le c\,g(n)$，就说 $f(n)=O(g(n))$，读作「$f$ 是大 $O$ of $g$」。
- 如果存在常数 $c>0$ 和 $n_0$，使得 $n\ge n_0$ 时 $f(n)\ge c\,g(n)$，就说 $f(n)=\Omega(g(n))$，读作「大欧米伽」。
- 同时有 $f=O(g)$ 和 $f=\Omega(g)$，就说 $f(n)=\Theta(g(n))$，读作「大西塔」。

**抓手：天花板、地板、夹住。** $O(g)$ 是天花板：$n$ 够大以后，$f$ 被 $g$ 的某个常数倍压在下面。$\Omega(g)$ 是地板：$f$ 被 $g$ 的某个常数倍托在上面。$\Theta(g)$ 是同时有天花板和地板，$f$ 被夹在 $g$ 的两个常数倍之间，增长速度就和 $g$ 一样。这个说法在一点上要小心：天花板可以很高，$n$ 的增长也被 $n^2$ 压在下面，所以 $n=O(n^2)$ 是对的，只是没提供多少信息；想表达「增长得恰好一样快」，要用 $\Theta$。

记号里的等号只是习惯，不是等式：$f=O(g)$ 读作「$f$ 属于增长不超过 $g$ 的那一类」，不能倒过来写成 $O(g)=f$。

**例 8**　例 4、例 5 数出的式子形状各异，现在用定义回答「只留最高项为什么可以」。证明 $3n^2+5n+20=\Theta(n^2)$。

地板：$n\ge1$ 时 $3n^2+5n+20\ge3n^2$，所以取 $c=3$，$n_0=1$，得 $\Omega(n^2)$。

天花板：想要 $3n^2+5n+20\le4n^2$，即 $n^2-5n-20\ge0$。$n=7$ 时是 $49-35-20=-6$，不行；$n=8$ 时是 $64-40-20=4$，成立。而且 $n\ge8$ 时 $n^2-5n-20=n(n-5)-20\ge8\cdot3-20>0$，所以取 $c=4$，$n_0=8$，得 $O(n^2)$。

上表也验证了这一点：$n\ge8$ 时 $f(n)$ 确实不超过 $4n^2$（$n=8$ 时 $252\le256$）。两个方向都成立，所以 $\Theta(n^2)$。

> 证明 $2n+7=\Theta(n)$。
>
> 答案：$n\ge1$ 时 $2n\le2n+7\le2n+7n=9n$，所以 $c=2$ 给 $\Omega(n)$，$c=9$、$n_0=1$ 给 $O(n)$。

**例 9**　这一道和例 8 的区别在于要证「不成立」。证明 $n^2\ne O(n)$。

$O$ 的定义是一句三层的话：存在 $c$、存在 $n_0$，对所有 $n\ge n_0$ 都有 $n^2\le cn$。这句话的否定，按 Z.3 的「出招」写法，是对方先给出任意的 $c$ 和 $n_0$，我们要能找到一个 $n\ge n_0$，使得 $n^2>cn$。

对任意的 $c$ 和 $n_0$，取 $n=\max(n_0,\lceil c\rceil+1)$（$\max(a,b)$ 是 $a,b$ 中较大的一个；$\lceil x\rceil$ 读作「$x$ 向上取整」，是不小于 $x$ 的最小整数，与向下取整相对）。这个 $n$ 满足 $n\ge n_0$，并且 $n>c$，两边乘以 $n$ 得 $n^2>cn$。所以不论对方给什么 $c$ 和 $n_0$，我们都有办法让它失败，$n^2$ 不是 $O(n)$。

**方法 3（定阶的规则）**

1. 常数倍丢掉：$c\cdot f=\Theta(f)$（$c>0$）。
2. 几项相加，留增长最快的那一项：$f+g=\Theta(\max(f,g))$。理由是 $\max(f,g)\le f+g\le2\max(f,g)$。
3. 程序各段依次执行时，先把次数相加，再取增长最快的部分。嵌套循环先固定外层变量，数出这一轮的内层次数，再对外层求和；只有每一轮内层次数相同时，才能直接相乘。
4. 比较增长阶时，对数可以选任意固定的大于 1 的底：$\log_a n=\dfrac{\ln n}{\ln a}$ 只差一个常数倍，所以 $\Theta(\log_2 n)=\Theta(\log_{10}n)$，本章不标底的 $\log n$ 都按这一约定理解，统一写成 $\Theta(\log n)$。

用它读前面的结果：`MAX` 是 $\Theta(n)$，`PAIRS` 是 $\Theta(n^2)$，例 5 的程序是 $\Theta(n\log n)$，顺序查找的最好情况是 $\Theta(1)$、最坏情况是 $\Theta(n)$。

### 4. $\log n$、$n^k$、$2^n$、$n!$ 谁长得快？

有了记号，就要比较常见的几类增长。拿它们在 $10^9$ 步每秒的机器上跑一跑：

| $n$ | $n^2$ | $2^n$ | $n!$ |
|---|---|---|---|
| 10 | 0.1 微秒 | 1 微秒 | 3.6 毫秒 |
| 20 | 0.4 微秒 | 1 毫秒 | 77 年 |
| 50 | 2.5 微秒 | 13 天 | $10^{48}$ 年 |
| 100 | 10 微秒 | $4\times10^{13}$ 年 | — |

按每秒 $10^9$ 步的假设，$n=100$ 对一个平方的程序是眨眼之间，对 $2^n$ 的程序，所需时间约为 $4\times10^{13}$ 年。再看 $n=10^8$ 的数据：$n^2=10^{16}$ 步，约 116 天；$n\log_2 n\approx2.7\times10^9$ 步，约 2.7 秒。几秒与近四个月，这就是同一件事换一个算法的差别。

要把这种差别说准，需要一个判别法。

**比较增长率的极限判别。** 设 $f,g$ 为正，$\lim\limits_{n\to\infty}\dfrac{f(n)}{g(n)}=L$。

- $L=0$：$f$ 比 $g$ 增长得严格慢，$f=O(g)$，但 $f\ne\Theta(g)$。
- $0<L<\infty$：$f=\Theta(g)$。
- $L=\infty$：$f$ 比 $g$ 严格快，$f=\Omega(g)$，但 $f\ne O(g)$。

理由是：$0<L<\infty$ 时，$n$ 够大以后 $\frac{L}{2}\le\frac{f}{g}\le2L$，正好是夹住的定义；$L=0$ 时，$n$ 够大以后 $\frac fg\le1$，所以有天花板，但比值趋于 0，任何 $c>0$ 的地板都托不住。$L=\infty$ 时反过来：$n$ 够大以后 $\frac fg\ge1$，所以 $f=\Omega(g)$；若还有 $f\le c\,g$，就得到 $\frac fg\le c$，与 $\frac fg\to\infty$ 矛盾，所以 $f\ne O(g)$。

下面是常用的四个极限，每个都给出理由：

1. **对数比幂慢。** 对 $a>0$，$\lim\limits_{n\to\infty}\dfrac{\ln n}{n^a}=0$。把 $n$ 换成连续变量 $x$，是 $\frac\infty\infty$ 型，用洛必达法则（C.7.2）：$\dfrac{1/x}{a x^{a-1}}=\dfrac{1}{a x^{a}}\to0$。
2. **幂比指数慢。** 对 $b>1$，$\lim\dfrac{n^k}{b^n}=0$。这里 $k>0$ 是固定的实数，先取不小于 $k$ 的整数 $m$。对 $x^m/b^x$ 连续用 $m$ 次洛必达法则，分子变成常数 $m!$，分母变成 $(\ln b)^mb^x$，比值趋于 0；又因为 $n\ge1$ 时 $0\le n^k/b^n\le n^m/b^n$，所以 $n^k/b^n\to0$。
3. **指数比阶乘慢。** $\dfrac{2^n}{n!}=\dfrac21\cdot\dfrac22\cdot\dfrac23\cdots\dfrac2n$，前两个因子乘积为 2，$n\ge3$ 以后每个因子 $\frac2k\le\frac23$，所以 $\dfrac{2^n}{n!}\le2\left(\dfrac23\right)^{n-2}\to0$。
4. **阶乘比 $n^n$ 慢。** $\dfrac{n!}{n^n}=\dfrac1n\cdot\dfrac2n\cdots\dfrac nn\le\dfrac1n\to0$，因为除第一个因子外，其余每个因子不超过 1。

![五条增长曲线的次序：纵轴取对数，每上一格大 10 倍。实线是 $n\log_2 n$ 和 $n^2$，虚线是 $n^3$，点线是 $2^n$，点划线是 $n!$；$n=10$ 附近 $2^n$ 才越过 $n^3$](fig/K31-n1.pdf){width=70%}

把它们串起来，从慢到快：

$$1\ \prec\ \log n\ \prec\ n^{a}\ (0<a<1)\ \prec\ n\ \prec\ n\log n\ \prec\ n^2\ \prec\ n^3\ \prec\ 2^n\ \prec\ n!\ \prec\ n^n,$$

其中 $f\prec g$ 表示 $\lim f/g=0$，即 $f$ 严格比 $g$ 慢。「$\log n$ 先于 $n^a$」来自第 1 个极限，「$n^3$ 先于 $2^n$」来自第 2 个。

注意 $\prec$ 说的是 $n$ 足够大以后。图上可以看到 $2^n$ 在 $n=4$ 追平 $n^2$（都是 16），$n\ge5$ 起超过它，却要到 $n=10$ 才超过 $n^3$（$10^3=1000<1024$）。所以规模很小的时候，一个阶更高的算法有可能更快，阶只管得了规模变大以后的事。

**方法 4（比较两个函数）**

1. 写出比值 $f(n)/g(n)$，化简。
2. 能求极限就按上面的判别读结果；比值里有 $\log n$ 对 $n^a$、$n^k$ 对指数的，就用上面的四个极限。
3. 要排一串函数的次序，只比相邻的两个。

**例 10**　例 8、例 9 只比较了两个函数，现在用方法 4 一次排五个。把 $n^2$、$n\log_2 n$、$2^n$、$n^{1.5}$、$(\log_2 n)^3$ 按增长从慢到快排序。

先凭感觉分类：一个对数的幂、几个 $n$ 的幂（带不带对数）、一个指数。再逐对核对：

$$\frac{(\log_2 n)^3}{n\log_2 n}=\frac{(\log_2 n)^2}{n}\to0,$$

$$\frac{n\log_2 n}{n^{1.5}}=\frac{\log_2 n}{\sqrt n}\to0,$$

$$\frac{n^{1.5}}{n^2}=\frac1{\sqrt n}\to0,\qquad\frac{n^2}{2^n}\to0 .$$

第一个比值的分子是 $\log n$ 的平方、分母是 $n$，由极限 1 趋于 0（$(\log n)^p/n^a=\bigl(\log n/n^{a/p}\bigr)^p$）；第二个同理；最后一个由极限 2。所以顺序是 $(\log_2 n)^3\prec n\log_2 n\prec n^{1.5}\prec n^2\prec2^n$。

> 把 $\log_2 n$、$\sqrt n$、$n\log_2 n$ 按增长从慢到快排序。
>
> 答案：$\dfrac{\log_2 n}{\sqrt n}\to0$（极限 1，取 $a=\frac12$），$\dfrac{\sqrt n}{n\log_2 n}=\dfrac1{\sqrt n\,\log_2 n}\to0$，所以 $\log_2 n\prec\sqrt n\prec n\log_2 n$。

**例 11**　这一道和例 10 的区别在于它是一道陷阱：指数里的常数不能像系数那样丢掉。判断 $2^{n+1}$、$2^{2n}$ 与 $2^n$ 的关系。

$\dfrac{2^{2n}}{2^n}=2^n\to\infty$，所以 $2^{2n}=4^n$ 严格比 $2^n$ 快，$2^{2n}\ne O(2^n)$。指数里乘一个常数，底就变了。

### 5. 大问题怎样交给小一号的自己？

求 $A[1]+\cdots+A[n]$ 可以用循环，也可以这样想：前 $n$ 项的和，等于前 $n-1$ 项的和加上 $A[n]$；而前 $n-1$ 项的和，是同一个问题，只是小了一号。把这个想法直接写成程序，函数就在自己的定义里调用自己，这叫**递归**：

```
SUM(A, n)
    if n = 0
        return 0
    return SUM(A, n − 1) + A[n]
```

递归程序有两部分。**出口**处理最小的情形，不再调用自己（这里 $n=0$，空和是 0）。**递归调用**把问题化成更小的同类问题，再把小问题的答案拼成大问题的答案。

跟踪递归，要记下哪些调用「还没做完在等」。对 $A=[5,2,8,1,9,3]$，`SUM(A, 6)` 一路向下调用到 `SUM(A, 0)`，再一路返回：

| 调用 | 它在等什么 | 返回值 |
|---|---|---|
| SUM(A, 6) | SUM(A, 5) + A[6] | 25 + 3 = 28 |
| SUM(A, 5) | SUM(A, 4) + A[5] | 16 + 9 = 25 |
| SUM(A, 4) | SUM(A, 3) + A[4] | 15 + 1 = 16 |
| SUM(A, 3) | SUM(A, 2) + A[3] | 7 + 8 = 15 |
| SUM(A, 2) | SUM(A, 1) + A[2] | 5 + 2 = 7 |
| SUM(A, 1) | SUM(A, 0) + A[1] | 0 + 5 = 5 |
| SUM(A, 0) | （出口） | 0 |

表从上往下是调用的顺序，从下往上是返回的顺序。同时等着的调用越多，占的内存越多：`SUM(A, n)` 最多同时有 $n+1$ 层，所以它用的额外空间是 $\Theta(n)$，而同样功能的循环只要常数个变量。

**怎样确信递归对？**用归纳法。这是 Z.4.5 的归纳法直接套在递归上，对应关系是：**出口对应归纳的起点，递归调用对应归纳假设。** 写递归时，只管相信小一号的调用已经答对，自己只负责把答案拼好。这个说法有一个前提：每次调用的参数必须真的变小，并且最终落到出口。否则 `BAD(n) = BAD(n) + 1` 这样的函数永远走不到出口。

**方法 5（用归纳法证明递归程序正确）**

1. 写清楚要证什么：对所有规模为 $n$ 的输入，程序返回应有的结果。
2. 起点：检查出口处的返回值对。
3. 归纳步：假设规模更小的调用都返回对，把它们的返回值代进递归调用那一行，推出规模为 $n$ 的调用也对。
4. 如果调用的规模不是 $n-1$（例如 $\lfloor n/2\rfloor$），第 3 步的假设用强归纳（Z.4.6）：假设所有比 $n$ 小的情形都对。

**例 12**　上面对 `SUM` 的追踪只验证了 $n=6$，现在证明对一切 $n$。证明 `SUM(A, n)` 返回 $A[1]+\cdots+A[n]$。

令 $P(n)$ 为「`SUM(A, n)` 返回 $A[1]+\cdots+A[n]$」，对 $n\ge0$ 归纳。

起点：$n=0$ 时程序返回 0，而空和等于 0，$P(0)$ 成立。

归纳步：设 $P(n-1)$ 成立（$n\ge1$）。程序返回 `SUM(A, n−1) + A[n]`，由归纳假设，前者是 $A[1]+\cdots+A[n-1]$，所以返回值是 $A[1]+\cdots+A[n]$，$P(n)$ 成立。

由归纳法，对一切 $n\ge0$ 成立。

> 仿例 12 证明：`FACT(n)` 在 $n=0$ 时返回 1，否则返回 `n * FACT(n − 1)`，则对一切 $n\ge0$ 它返回 $n!$。
>
> 答案：起点 $n=0$ 返回 $1=0!$。归纳步：设 `FACT(n−1)` 返回 $(n-1)!$，则 `FACT(n)` 返回 $n\cdot(n-1)!=n!$。

接下来的例题把「小一号」换成「小一半」。本例设 $a$ 为非零实数，$n$ 为非负整数。要算 $a^n$，$n\ge1$ 时逐个乘要 $n-1$ 次乘法。但 $n$ 是偶数时 $a^n=(a^{n/2})^2$，一次乘法就把一半大小的问题拼成了整个问题；$n$ 是奇数时 $a^n=(a^{\lfloor n/2\rfloor})^2\cdot a$，多乘一个 $a$。

```
POW(a, n)
    if n = 0
        return 1
    h ← POW(a, ⌊n / 2⌋)
    if n 是偶数
        return h * h
    return h * h * a
```

**例 13**　这一道和例 12 的区别在于递归调用的参数是 $\lfloor n/2\rfloor$。追踪 `POW(3, 10)`，并证明 `POW` 对所有 $n\ge0$ 都对。

追踪：参数依次是 $10\to5\to2\to1\to0$，到出口后返回：

| 调用 | $h$ | 返回值 | 这一层的乘法次数 |
|---|---|---|---|
| POW(3, 0) | | 1 | 0 |
| POW(3, 1) | 1 | $1\cdot1\cdot3=3$ | 2 |
| POW(3, 2) | 3 | $3\cdot3=9$ | 1 |
| POW(3, 5) | 9 | $9\cdot9\cdot3=243$ | 2 |
| POW(3, 10) | 243 | $243\cdot243=59049$ | 1 |

结果 $3^{10}=59049$ 对，一共做了 6 次乘法，逐个乘要 9 次。

证明：令 $P(n)$ 为「`POW(a, n)` 返回 $a^n$」。调用的参数是 $\lfloor n/2\rfloor$，不是 $n-1$，所以用强归纳。

起点：$n=0$ 返回 1，$a^0=1$。

归纳步：设 $n\ge1$，且所有小于 $n$ 的情形都对。因为 $\lfloor n/2\rfloor<n$，由假设 $h=a^{\lfloor n/2\rfloor}$。分两种情况：

- $n=2q$ 是偶数：$\lfloor n/2\rfloor=q$，返回 $h\cdot h=a^{q}\cdot a^{q}=a^{2q}=a^n$。
- $n=2q+1$ 是奇数：$\lfloor n/2\rfloor=q$，返回 $h\cdot h\cdot a=a^{2q}\cdot a=a^{2q+1}=a^n$。

两种情况都对，$P(n)$ 成立。

> 追踪 `POW(2, 13)`，写出每层的参数和返回值。
>
> 答案：参数依次为 $13\to6\to3\to1\to0$，返回值依次为 1（$n=0$）、$1\cdot1\cdot2=2$（$n=1$）、$2\cdot2\cdot2=8$（$n=3$）、$8\cdot8=64$（$n=6$）、$64\cdot64\cdot2=8192$（$n=13$）。共 7 次乘法。

每次递归把参数取整减半，返回时用 1 次或 2 次乘法合并，所以 $n\ge1$ 时这个程序的递归深度只有 $\lfloor\log_2 n\rfloor+2$ 层，其中包含 $n=0$ 的出口那一层（$n=10$ 时是 5 层，参数是 10、5、2、1、0），每层的额外空间固定，总额外空间 $\Theta(\log n)$。

最后看一个递归写得很自然、效率却出奇地差的例子。K2.1.3 里的斐波那契数满足 $F(n)=F(n-1)+F(n-2)$，$F(0)=0$，$F(1)=1$，照抄成程序：

FIB(n)
    if n ≤ 1
        return n
    return FIB(n − 1) + FIB(n − 2)

它的正确性是方法 5 的第 4 条的直接应用。这里要分清两个东西：`FIB` 是程序，$F$ 是斐波那契数列的定义。对 $n$ 用强归纳证明「`FIB(n)` 返回 $F(n)$」：$n=0,1$ 时程序直接返回 $n$，与 $F(0)=0$、$F(1)=1$ 一致；设所有小于 $n$ 的情形都对，特别地 `FIB(n−1)` 返回 $F(n-1)$，`FIB(n−2)` 返回 $F(n-2)$，所以 `FIB(n)` 返回 $F(n-1)+F(n-2)=F(n)$。

### 6. 递归函数要跑多久？

回头看第 5 节里 `SUM(A, 6)` 的追踪表：除出口外的 6 层调用各做一次加法，共 6 次。要对一般的 $n$ 数清，得到的也是一个递归的式子。设 $T(n)$ 是规模为 $n$ 的输入上的基本操作数：一次调用自己做的工作，加上它调用的各个小调用的 $T$。

对 `SUM` 数加法：自己做一次加法，再加上 `SUM(A, n−1)` 的次数，所以

$$T(n)=T(n-1)+1,\qquad T(0)=0 .$$

**方法 6（展开法）**

1. 写出递推式和初值。
2. 把右边出现的 $T$ 用同一个递推式再换一次，换几次，直到看出规律。
3. 把规律写成「换了 $k$ 次以后」的式子。
4. 让 $k$ 走到出口，代入初值，得到公式。
5. 想确信不出错，就用归纳法验证一遍公式（K2.1 的做法）。

**例 14**　用展开法对一般的 $n$ 求 `SUM` 的加法次数 $T(n)=T(n-1)+1$，$T(0)=0$。

从 $T(n)$ 开始，第一次用递推式得到 $T(n-1)+1$；第二次把 $T(n-1)$ 也换掉，得到 $T(n-2)+2$；第三次得到 $T(n-3)+3$。规律是展开 $k$ 次后 $T(n)=T(n-k)+k$。

让 $k=n$，走到出口 $T(0)=0$：

$$T(n)=T(0)+n=n .$$

所以递归求和做 $n$ 次加法，$\Theta(n)$，和循环的数目相同。

> 用展开法解 $T(n)=T(n-1)+2$，$T(0)=1$。
>
> 答案：展开 $k$ 次后 $T(n)=T(n-k)+2k$，取 $k=n$ 得 $T(n)=T(0)+2n=2n+1$。

**例 15**　这一道和例 14 的区别在于一次调用要变成两次小调用。汉诺塔：三根柱子，$n$ 个大小不同的盘子，每次搬一个，大盘子不能压在小盘子上，要把全部盘子从柱 1 搬到柱 3。递归的搬法是：先把上面 $n-1$ 个盘子搬到柱 2，再把最大的盘子搬到柱 3，最后把 $n-1$ 个盘子从柱 2 搬到柱 3。求按这种搬法总共要搬动的次数 $H(n)$（本章只数这种搬法，不讨论它是不是最少）。

按搬法，$H(n)=2H(n-1)+1$，$H(1)=1$。直接展开：

$$H(n)=2H(n-1)+1=2\bigl(2H(n-2)+1\bigr)+1=4H(n-2)+3=8H(n-3)+7=\cdots=2^{k}H(n-k)+(2^k-1).$$

规律是展开 $k$ 次后，系数是 $2^k$，常数项是 $1+2+\cdots+2^{k-1}=2^k-1$。这个规律是从前几次展开看出来的，可以用归纳法验证：$k=1$ 时就是递推式本身；设换 $k$ 次后成立，把 $H(n-k)=2H(n-k-1)+1$ 代入，得 $2^k\bigl(2H(n-k-1)+1\bigr)+2^k-1=2^{k+1}H(n-k-1)+2^{k+1}-1$，正是换 $k+1$ 次的形式。取 $k=n-1$，走到 $H(1)=1$：

$$H(n)=2^{n-1}\cdot1+2^{n-1}-1=2^n-1 .$$

$n=3$ 时 7 次，$n=10$ 时 1023 次，$n=64$ 时约 $1.8\times10^{19}$ 次。

**例 16**　同样是两次小调用，`FIB` 的次数怎样？设 $C(n)$ 是计算 $\mathrm{FIB}(n)$ 所做的调用总数（包括自己）。先猜一猜：计算 $\mathrm{FIB}(30)$ 要调用几次，几百、几万，还是几百万？

调用数 $C$ 满足

$$C(n)=C(n-1)+C(n-2)+1,\qquad C(0)=C(1)=1 .$$

算出前几项：1, 1, 3, 5, 9, 15, 25, 41, 67, 109, 177。递推式里多出的那个 $+1$ 碍事，把每一项加 1 试试，得 2, 2, 4, 6, 10, 16, 26, 42, ……。这时 $C(n)+1=\bigl(C(n-1)+1\bigr)+\bigl(C(n-2)+1\bigr)$，和斐波那契数的递推 $F(n)=F(n-1)+F(n-2)$ 是同一个形状，而 $2,2,4,6,10,16$ 正是 $2F(1),2F(2),\dots,2F(6)$（这里 $F(1)=F(2)=1$）。于是猜 $C(n)+1=2F(n+1)$，即 $C(n)=2F(n+1)-1$。用强归纳验证：$n=0,1$ 时 $2F(1)-1=2F(2)-1=1$；设对 $n-1$、$n-2$ 成立，则

$$C(n)=\bigl(2F(n)-1\bigr)+\bigl(2F(n-1)-1\bigr)+1=2\bigl(F(n)+F(n-1)\bigr)-1=2F(n+1)-1 .$$

K2.1.3 的通项说明 $F(n)\approx\frac{1}{\sqrt5}\left(\frac{1+\sqrt5}{2}\right)^n$，所以 $C(n)=\Theta(\varphi^n)$，其中 $\varphi=\frac{1+\sqrt5}{2}\approx1.618$。$\mathrm{FIB}(30)$ 要 2 692 537 次调用，$\mathrm{FIB}(40)$ 要 331 160 281 次。

为什么这么多？画出调用的树，就看见原因：

#### 子问题各自减半时，怎样看出规律？

前面是一个一个换，遇到复杂的递推式就不好看出规律。更直观的办法是画**递归树**：每次调用是一个结点，结点上写这次调用自己做的工作（不含它调用的小问题），所有结点的工作量加起来就是 $T(n)$。我们按层加。

**例 17**　和例 15 一样一次调用分成两个子问题，但每个子问题只有原来的一半大，一个一个换已经难看出规律，改用递归树。求 $T(n)=2T(n/2)+n$，$T(1)=1$，设 $n=2^k$。

这个式子是说：一次调用自己做 $n$ 的工作，再分成两个规模减半的子问题。画树，数每层：

- 第 0 层：1 个结点，规模 $n$，自己做 $n$，这一层共 $n$。
- 第 1 层：2 个结点，规模 $n/2$，各做 $n/2$，这一层共 $n$。
- 第 $i$ 层：$2^i$ 个结点，规模 $n/2^i$，各做 $n/2^i$，这一层共 $2^i\cdot\frac{n}{2^i}=n$。
- 最后一层 $i=k$：规模 1，结点 $2^k=n$ 个，各做 1，共 $n$。

![$T(n)=2T(n/2)+n$ 的递归树（$n=8$）。每个圆里是该次调用自己的工作量，右侧是该层之和，每层都是 8，共 4 层](fig/K31-n3.pdf){width=70%}

每层工作量相同，层数是 $k+1=\log_2 n+1$，所以

$$T(n)=n(\log_2 n+1)=\Theta(n\log n) .$$

检查 $n=8$：$T(2)=2\cdot1+2=4$，$T(4)=2\cdot4+4=12$，$T(8)=2\cdot12+8=32=8\times4$。

> 用递归树求 $T(n)=2T(n/2)+1$，$T(1)=1$（$n=2^k$）。
>
> 答案：第 $i$ 层有 $2^i$ 个结点，各做 1，共 $2^i$；一共 $k+1$ 层，总和 $\sum_{i=0}^{k}2^i=2^{k+1}-1=2n-1$，所以是 $\Theta(n)$。每层的工作量成倍增长：叶子层做 $n$ 步，占总量 $2n-1$ 的一半以上，其余各层合计 $n-1$ 步，所以叶子层已能决定总量的阶。

**例 18**　这一道和例 17 的区别在于子问题只有一个，每层工作量反过来递减。求 $T(n)=T(n/2)+n$，$T(1)=1$（$n=2^k$）。

第 $i$ 层只有 1 个结点，规模 $n/2^i$，自己做 $n/2^i$。各层是 $n,\ n/2,\ n/4,\dots,1$，总和

$$T(n)=n+\frac n2+\frac n4+\cdots+1=2n-1=\Theta(n).$$

这时根层做 $n$ 步，其余各层合计 $n-1$ 步，所以根层占总量的一半以上，并决定总量的阶。

三棵树放在一起看：例 17 每层相等，答案是「层数乘每层」；例 17 后面那道题每层成倍变大，答案由叶子那一层决定；例 18 每层成倍变小，答案由根那一层决定。下一节把这个规律写成公式。

### 7. $T(n)=aT(n/b)+n^d$ 能不能直接写出阶？

很多递归程序都是这种形态：把规模为 $n$ 的问题分成 $a$ 个规模为 $n/b$ 的子问题，再花 $n^d$ 的工作把答案合并。例 17、18 各算了一种。先换一组数，看按层加会出现什么：$T(n)=3T(n/2)+n$，取 $n=8$。第 0 层 1 个结点，工作 8；第 1 层 3 个结点，各做 4，共 12；第 2 层 9 个结点，各做 2，共 18；第 3 层 27 个结点，各做 1，共 27。每层是上一层的 $\frac32$ 倍，叶子层最重，总数 $8+12+18+27=65$，与直接用递推式算出的 $T(2)=5$、$T(4)=19$、$T(8)=65$ 一致。把这里的 $3,2,1$ 换成一般的 $a,b,d$，每一步照样走一遍：

设 $a,b$ 为固定正整数，$b\ge2$，$d\ge0$ 为固定实数，只考虑 $n=b^k$（$k$ 为非负整数），且 $T(n)=aT(n/b)+n^d$，$T(1)=1$。

**第 1 步：数每一层有多少工作。** 第 $i$ 层有 $a^i$ 个结点，每个规模为 $n/b^i$，自己做 $(n/b^i)^d$ 的工作，所以这一层共

$$a^i\left(\frac n{b^i}\right)^d=n^d\left(\frac{a}{b^d}\right)^i .$$

**第 2 步：把各层加起来。** 记 $r=\dfrac a{b^d}$，层数从 $i=0$ 到 $i=k=\log_b n$，所以

$$T(n)=n^d\sum_{i=0}^{k}r^i .$$

这是一个等比数列，根据公比 $r$ 与 1 的大小分三种情况。

**第 3 步：分情况。**

- $r<1$（$a<b^d$）：各层递减，和 $\sum_{i=0}^{k}r^i<\sum_{i=0}^{\infty}r^i=\dfrac1{1-r}$ 是常数，所以 $T(n)=\Theta(n^d)$，由根决定。
- $r=1$（$a=b^d$）：各层相等，共 $k+1=\log_b n+1$ 项，所以 $T(n)=\Theta(n^d\log n)$。
- $r>1$（$a>b^d$）：各层递增，等比和夹在最后一项 $r^k$ 与 $\dfrac{r}{r-1}r^k$ 之间，所以 $T(n)=\Theta(n^dr^k)$。而

$$n^dr^k=n^d\cdot\frac{a^k}{b^{dk}}=n^d\cdot\frac{a^{\log_b n}}{n^d}=a^{\log_b n}=n^{\log_b a},$$

最后一步用了 $a^{\log_b n}=n^{\log_b a}$（两边取以 $b$ 为底的对数，都是 $\log_b a\cdot\log_b n$）。这也是叶子的个数。

![三种公比下各层的工作量（横条越长越多）。$r<1$ 时根最长，$r=1$ 时各层一样长，$r>1$ 时叶子层最长；虚线标出决定总量的那一层；图中的数字是该层工作量与根层工作量的比，不是绝对步数](fig/K31-n4.pdf){width=70%}

把三种情况合起来，就是**主定理**：

$$T(n)=aT(n/b)+n^d\ \Longrightarrow\ T(n)=\begin{cases}\Theta(n^d), & a<b^d,\\[2pt]\Theta(n^d\log n), & a=b^d,\\[2pt]\Theta\bigl(n^{\log_b a}\bigr), & a>b^d.\end{cases}$$

以上推导针对 $n=b^k$，本书的题目也都取 $n=b^k$；处理任意规模时要先写明子问题怎样取整，再另行核对。

**方法 7（主定理）**

1. 认出三个数：子问题个数 $a$，每个子问题的规模缩小的倍数 $b$，合并的工作 $n^d$。
2. 比较 $a$ 与 $b^d$。
3. 三种情况各对应一个阶：根重（$a<b^d$）、层层相等（$a=b^d$）、叶子重（$a>b^d$）。
4. 如果递推式不是这个形状，回到递归树。

**例 19**　这一道直接用方法 7，把例 17、18 的三种结果套进公式，检验公式和递归树的结论一致。用主定理求下面各式的阶。

| 递推式 | $a$ | $b$ | $d$ | $b^d$ | 情况 | 阶 |
|---|---|---|---|---|---|---|
| $T(n)=T(n/2)+1$ | 1 | 2 | 0 | 1 | $a=b^d$ | $\Theta(\log n)$ |
| $T(n)=2T(n/2)+n$ | 2 | 2 | 1 | 2 | $a=b^d$ | $\Theta(n\log n)$ |
| $T(n)=4T(n/2)+n$ | 4 | 2 | 1 | 2 | $a>b^d$ | $\Theta(n^{\log_2 4})=\Theta(n^2)$ |
| $T(n)=3T(n/2)+n$ | 3 | 2 | 1 | 2 | $a>b^d$ | $\Theta(n^{\log_2 3})$，其中 $\log_2 3\approx1.585$ |
| $T(n)=2T(n/2)+n^2$ | 2 | 2 | 2 | 4 | $a<b^d$ | $\Theta(n^2)$ |
| $T(n)=8T(n/2)+n^2$ | 8 | 2 | 2 | 4 | $a>b^d$ | $\Theta(n^3)$ |

> 用主定理求 $T(n)=9T(n/3)+n$ 的阶（$n=3^k$）。
>
> 答案：$a=9$，$b=3$，$d=1$，$b^d=3<9=a$，叶子重，$T(n)=\Theta(n^{\log_3 9})=\Theta(n^2)$。

第一行里 $d=0$ 表示合并只花常数时间；它就是 K3.3 里二分查找的递推式：每次问一个问题，规模减半。

第三、四行说明 $a$ 比 $b^d$ 大一点点，阶就从 $n$ 的 1 次方跳到 $n^{\log_2 3}$（指数约 1.585）甚至 $n^2$：叶子重的时候，决定一切的是分出去的子问题有多少个。第四行正是前面按层加过的 $T(n)=3T(n/2)+n$。

**例 20**　这一道和例 19 的区别在于递推式的形状不符合主定理。判断下面三个能不能直接用，不能的怎样处理。

1. $T(n)=T(n-1)+n$：规模是减 1，不是除以 $b$，不符合。设 $T(1)=1$，用展开法：$T(n)=1+2+\cdots+n=\frac{n(n+1)}2=\Theta(n^2)$。
2. $T(n)=2T(n/2)+n\log_2 n$：合并的工作不是 $n^d$，不符合。画树，第 $i$ 层共 $2^i\cdot\frac{n}{2^i}\log_2\frac n{2^i}=n(\log_2 n-i)$，各层加起来是 $n(\log_2 n+(\log_2 n-1)+\cdots+1)$，再加上叶子的 $n$，仍是 $\Theta(n\log^2 n)$。如果硬按主定理的 $a=b^d=2$ 那一行读，会得到 $\Theta(n\log n)$，少了一个 $\log n$：合并的工作必须恰好是 $n^d$ 的形状，这个条件不能去掉。
3. $T(n)=T(n/3)+T(2n/3)+n$：两个子问题大小不同，不符合。画树：每次分裂把规模原样分给两个子结点，所以每层的规模之和不超过 $n$，而内部结点自己做的工作就是它的规模，每层大约做 $n$。剩下的问题是树有几层：最短的一条路每次除以 3，最长的一条每次乘 $\frac23$，层数夹在 $\log_3 n$ 与 $\log_{3/2}n$ 之间，两者只差常数倍，所以总量应当是 $n\log n$ 的阶。下面把它写严。$n/3$ 与 $2n/3$ 不一定是整数，这里让规模取正实数（只影响低阶项，不影响阶），约定 $0<x\le1$ 时 $T(x)=1$，$x>1$ 时 $T(x)=T(x/3)+T(2x/3)+x$。

   上界：规模大于 1 的内部结点，工作等于规模。叶子的父结点规模大于 1，所以叶子规模大于 $\frac13$，它的 1 步工作小于规模的 3 倍。于是每个结点的工作不超过规模的 3 倍，每层不超过 $3n$。规模每次至多乘 $\frac23$，沿任一条路至多 $\lceil\log_{3/2}n\rceil$ 次分裂就到出口，所以层数与 $\log n$ 同阶，$T(n)=O(n\log n)$。

   下界：$n\ge3$ 时看深度 $i=0,1,\dots,\lfloor\log_3 n\rfloor-1$ 的各层。这些层里最小的结点规模是 $n/3^i\ge3>1$，没有结点提前结束，全都继续分裂，所以每层的工作恰好是规模之和 $n$。这样的层有 $\lfloor\log_3 n\rfloor$ 个，总工作至少是 $n\lfloor\log_3 n\rfloor$，即 $\Omega(n\log n)$。上下两边合起来是 $\Theta(n\log n)$。

第 3 种形状会在快速排序里出现：划分得不均匀，两边大小不等，但只要比例固定，阶仍然是 $n\log n$。

回到开头的问题：50 毫秒的预算是 $5\times10^7$ 步，商品有 $n=10^8$ 件。逐件扫一遍是 $\Theta(n)$，要 $10^8$ 步，已经超出预算一倍；就算做到 $\Theta(n\log n)$，也要约 $2.7\times10^9$ 步。预算里放得下的，是每问一个问题就把候选范围减半的做法，它的递推式是例 19 第一行的 $T(n)=T(n/2)+1$，阶为 $\Theta(\log n)$，$n=10^8$ 时只需约 27 步。所以逐件比较行不通，要靠把范围成倍缩小；K3.3 讲二分查找时会看到它怎样用在真正的数据上。

合上书，推出 $T(n)=aT(n/b)+n^d$ 的第 $i$ 层工作量，并说明三种情况各由哪一层决定。
